# Островок

Мультиплатформенное приложение Flutter для подбора отелей, мотелей, хостелов, туров и перелётов. Островок — турагент-маскот: сначала спрашивает страны и приоритеты, затем показывает карточки. Свайп вправо / влево учит рекомендации.

Сейчас это **первая рабочая версия**: без Google / Apple / почты и без живой оплаты. Flutter-клиент подключается к Go API, а при недоступном сервере автоматически продолжает работать с локальным каталогом.

## Что уже есть

1. Онбординг с маскотом, выбором стран и того, что важно в поездке. Кнопка **Пропустить** на каждом шаге.
2. Если пользователь пропускает подбор — на главной универсальные предложения (средний бюджет, города и море).
3. Карточки в механике Tinder: вправо — нравится, влево — мимо. Есть кнопки сердца и крестика.
4. Карточка открывается: описание, удобства, отзывы. Оттуда тоже можно лайкнуть или отклонить.
5. Нижняя панель: **Карточки**, **Агент**, **Матчи**, **Кабинет**.
6. Свайп летит в Go (`POST /v1/swipes`), пишется в PostgreSQL `user_swipes`, SQL пересчитывает теги, на экран приходит новая колода.
7. Агент отвечает на подбор, бронь, отложенную бронь и вызов менеджера; поиск по городу/бюджету идёт по Postgres.
8. Docker Compose: PostgreSQL 15 + Redis + Go API. Схема и 5 карточек — файлы Ольги из `analytics/` (`init.sql`, `mock_data.sql`).
9. Офлайн-резерв: если API или база не запущены, клиент продолжает на локальном каталоге.

Авторизация выключена флагом `FeatureFlags.authEnabled = false` в `ios/Ostrovok/Ostrovok/FeatureFlags.swift`. Когда дойдём до входа — включим флаг и допишем экран.

## Как устроены рекомендации

Живой путь хакатона:

телефон → `POST /v1/swipes` → строка в `user_swipes` → SQL по тегам лайков → новая карточка в ответе.

Код: `backend/internal/store/postgres.go`. Локальный запасной ранжир: `backend/internal/recommend` и `mobile/lib/services/recommendation_engine.dart`.

Фото мест лежат в `mobile/assets/places` и отдаются API с `/static/places`.

## Как запустить мобильное приложение

Основной клиент: `mobile`.

Нужны **Docker** (Postgres) и два терминала:

```powershell
docker compose up --build
.\scripts\run-mobile.ps1
```

Проверка базы и API: http://127.0.0.1:8080/health — в JSON должно быть `"store":"postgresql"`.

Без Docker API поднимется в памяти (для юнит-тестов), но жюри это засчитает как заглушку.

На Windows собирается Android (нужны Android Studio и эмулятор). Тот же Flutter-код собирается для iOS на Mac. Из-за кириллицы в пути `D:\Разработка` скрипты автоматически подключают диск `Z:`.

Подробности, APK/AAB и физический телефон: [docs/FLUTTER.md](docs/FLUTTER.md).

## Старый SwiftUI-прототип

Нужен Mac с Xcode 15+ и iOS 17. На Windows симулятор Apple не собирается.

1. Запустите API: `docker compose up --build` или скриптом из `scripts`.
2. Откройте `ios/Ostrovok/Ostrovok.xcodeproj`.
3. Выберите симулятор iPhone.
4. Team в Signing: ваш Apple ID.
5. Run.

Сброс онбординга: вкладка **Кабинет** → «Сбросить онбординг и свайпы».

## Как запустить Go API

```bash
cd backend
go test ./...
go run ./cmd/api
```

- `GET /health`
- `GET /v1/catalog` — предложения, страны, приоритеты
- `GET /v1/offers` и `GET /v1/offers/{id}`
- `POST /v1/recommendations` — тело: `countryCodes`, `priorityIDs`, `skipped`, `swipes`
- `POST /v1/agent/chat` — тело: `message`, `liked`, `guestId`; бронь/менеджер создают тикет
- `POST /v1/bookings` и `GET /v1/bookings?guestId=`
- `POST /v1/manager/tickets` и `GET /v1/manager/tickets?guestId=`

## Что сознательно не делали в этом шаге

- Вход через Google, Apple ID, почту и пароль.
- Реальные фото, платежи, календарь дат, пуши.
- Живой LLM: агент на правилах, чтобы поток можно было тыкать без ключей.
